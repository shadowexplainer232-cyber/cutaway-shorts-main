# Cutaway: free cloud pipeline for YouTube Shorts

Everything runs on GitHub Actions. Your PC is only needed once (step 3). Nothing here publishes a
video publicly: uploads are always **private**, and you press Publish in YouTube Studio.

## What is in the box
| Path | Purpose |
|---|---|
| `episodes/*.yml` | One file per Short: script, on-screen text, titles, description, hashtags, sources, status |
| `config/brand.yml` | Colours, voice, speed, music (all PROPOSED until you approve the branding) |
| `src/tts.py` | Narration with Piper (downloads the voice on first run), joins scenes into WAV + MP3 |
| `src/visuals.py` | Draws the cutaway animation and subtitles with Pillow (1080x1920) |
| `src/build_video.py` | Pipes frames to FFmpeg: H.264 + AAC MP4 |
| `src/upload_youtube.py` | Private upload through the YouTube Data API |
| `.github/workflows/build-short.yml` | Manual run, plus Mon/Wed/Fri 09:00 IST schedule |
| `voices/VOICES.md` | Voice options and licence checks |

Run one from GitHub: Actions > Build Cutaway Short > Run workflow > episode `002`, tick `test_mode`
(skips the draft/approval checks and never uploads). Visual types are in `src/visuals.py`,
`src/visuals_jet.py` and `src/visuals_turbo.py`; each scene picks one with `visual: {type: ...}`.

## Pace
`config/brand.yml`: `voice.length_scale` (1.25 = about 25% slower than Piper's default, which was ~190
words/min) and `pad_after_scene_sec` (0.6 s after every scene). Any episode can override the speed
with `length_scale:` and any scene can hold a longer beat with `pause_after:` (seconds).

## Sound, voice and 3D
- **Narration:** Piper reads each scene. Set `voice.effect: robot` in `config/brand.yml` for a mechanical-sounding voice (untested on real speech: audition it before using it).
- **Mechanical sound effects:** generated by `src/sfx.py` (valve clicks, intake whoosh, spark zap, power thump, exhaust puff, brand ding, quiet engine idle). Each scene lists its effects under `sfx:` in the episode file. No downloads, no licensing issues.
- **Opening and ending:** the first scene is a surprising hook; the last scene is a Cutaway brand outro (logo, tagline, "Follow for more", next-episode teaser).
- **3D engine:** `blender/engine_cycle.py` builds a cutaway engine with real piston/crank motion and renders one 720-degree loop on the GitHub runner (first run is slow, then cached). If Blender is missing or fails, the 2D animation is used automatically.

## Approval gates (by design)
1. You set `status: approved` in an episode file. Only then will the scheduled job build it.
2. The build refuses unless `sources_status: VERIFIED` (fact-check first).
3. Uploads go up as private. You publish in YouTube Studio.

## Setup (about 30 minutes, free)
1. Create a free GitHub account and a **public** repo (public repos get unlimited Actions minutes on standard runners; private repos have a monthly allowance. Verify current figures in GitHub billing docs). Upload this folder's contents.
2. In Google Cloud Console: create a project, enable **YouTube Data API v3**, create an OAuth client (type Desktop), download `client_secret.json`.
3. On any computer with a browser, once: `python src/get_refresh_token.py client_secret.json` and sign in with the channel's Google account. It prints a refresh token.
4. In the repo: Settings > Secrets and variables > Actions > add `YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN`.
5. Actions tab > "Build Cutaway Short" > Run workflow with the episode path. Leave "upload" off for the first runs and download the MP4 from the run's artifacts to check it.

## Test locally (no voice needed)
`python -m src.run_episode episodes/001-four-stroke-engine.yml --tts stub --force`
makes a silent test video. Stub renders are never uploaded.

## NOT yet verified (be honest with yourself about these)
- **The Blender script has never been run** (no Blender where it was written). Expect to adjust camera, materials or lighting after the first render. The download URL for Blender 4.2.3 should be checked, and Cycles on a free CPU runner may take a long time; lower `blender.frames` or `blender.samples` if so.
- The robot voice filter ran on a test tone only, not on speech.
- The sound effects were checked to be present in the audio, but nobody has listened to them. Judge them by ear and tell me what to change.
- Piper CLI flags and the exact voice id were written from memory and **never run**. The first workflow run is the real test.
- Voice licences for commercial use: see `voices/VOICES.md`.
- New YouTube API projects can be limited to private uploads until Google audits them. That fits this workflow, but means no auto-public publishing.
- API quota: an upload costs far more units than a read. Check Google's quota page. Default daily quota should still allow a few uploads a day.
- GitHub disables scheduled workflows in repos with no activity for a long time.
- Sample episode facts (four strokes, 720 degrees, one power stroke per two revolutions, 3,000 rpm = 1,500 cycles per minute per cylinder) are standard engineering knowledge, but cite sources before approving.
- The animation is simplified (no valve overlap); the video says so on screen.
